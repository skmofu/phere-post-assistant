インスタとJOURNALに同時に載ります。ここが最後の関所です。
自動化の度合いは、取り消せるかどうかで分けています ホームページの記事は、あとから下書きに戻せます。だから全自動でも安全です。インスタは一度出すと取り消せないので、必ずお二人の「OK」を待ちます。
現在地（8/13時点） AIの下書きと承認画面は本物です（17番＝公開URLでお二人の端末でも動きます。キーはURLで運び、サーバーにも保管場所にも残りません）。インスタへの投稿は、いまは「本文をコピー→Instagramに貼り付け（約30秒）」の橋渡し運用。JOURNALの自動化はホームページの管理情報が分かってからフェーズB、インスタの「OK→自動投稿」はフェーズCで配線します。

4裏側の仕組み　マスター用メモ

パイプライン（Mac Studio・launchd 30分間隔）

  1. 新着検知　Drive API ／ IMAP
  2. 前処理　HEIC→JPEG／リサイズ（WP用1600px・IG用1080px）／EXIF除去（位置情報）／知覚ハッシュで重複判定
  3. 分岐A：JOURNAL（全自動）　POST /wp-json/wp/v2/media（画像）→ POST /wp-json/wp/v2/posts（本文＝AI下書き・カテゴリJOURNAL）。認証はWP標準のアプリケーションパスワード（プラグイン不要）、Macのキーチェーン保管。誤投稿はWP上で下書き戻し／削除で即復旧
  4. 分岐B：インスタ（半自動）　3温度キャプション生成→承認依頼→「OK」検知→Meta Graph APIで投稿（JOURNAL同時掲載がONなら分岐Aも同時発火）
  5. ログ　投稿台帳（何を・いつ・どこへ）

インスタ側の前提（第2回で一緒に）

@phere_hair のプロアカウント化＋FBページ連携 → Meta開発者アプリ → 長期トークン。暫定はMeta Business Suiteの予約投稿（人力5分／週）。

順番に注意 作成直後の新規アカウントへ即座にAPI自動投稿を接続するのは、制限・凍結のリスクが最も高いパターン。まず手動投稿で2〜4週間の運用実績を作ってからフェーズCへ進む。
